## Do

1. **Where it lives:** `src/boards/game/` (core from #95, plus `shift.js`, `score.js`, `ui.js`); the converter
   bundles it into `hubs/boards/game/chairside.js` (one IIFE, stamped `?v=<hash>`, failing over 110 KB gzipped).
   `hubs/boards/content/arcade.js` is the skin: it returns `{ startGame, stopAll, current }` and loads the bundle on
   first start; no lobby of its own (build-a-hub on `main`: the engine draws the lobby). `SH_HUB.arcade`:
   `games: ["chairside"]`, `first: "chairside"`. A new arcade game id needs its migration line (the arcade's list of
   games, as `migration_v40.sql` did): fetch `main` for the next free number, and list it in
   `supabase/pending-migrations.txt`.
2. **The adapter (replaces BUILD_SPEC 6.3):** the game reads units, questions, cases and the patient box from the engine
   (`HX`), draws each item with the engine's card in lock-in mode (pick, then Sure / Unsure / Guess; feedback deferred
   on a booked patient), and records through the engine's one answer path with `ctx: "game"`. `conf` goes on the
   answered event's detail; if `record_answer_v2` should keep it, say so in the PR (it doesn't today) rather than
   changing the database here.
3. **Today's shift** is the Daily Drill's set from `shPlan`: finishing either one finishes both. Recall patients are due
   items, callbacks recent misses and Sure-wrongs (BUILD_SPEC 1.5 and 6.2).
4. **Scoring** (`score.js`, pure): Care and Flow exactly as BUILD_SPEC 6.2's table; the skim guard; BUILD_SPEC 6.6's
   tests in `tools/ci/chairside.test.js` (CI runs it): for simulated students at accuracy 0.25-0.95 on 3-5 options,
   honest locking is never beaten and always-Sure / always-Guess never top a seeded comparison.
5. **Saving:** a shift in progress is kept on the device for the day (resumable); nothing else is saved by the game. No
   `game_saves` table.
6. **Phone first:** playable silent, nothing in the bottom-left 90 x 90 px (Timmy), the patient box collapsed after the
   first item of a booked patient (T-10's rule).
