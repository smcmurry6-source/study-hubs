## What to build

**Card (`20-card.js`)**

- `renderItem(el, qid, opts) -> { picked(), submit(conf), destroy() }` with `opts = { ctx, lockIn, deferFeedback,
  shuffle, review }` (BUILD_SPEC 6.3). The bank, cases, drill and later the game and mock all go through it.
- Shuffle on every render unless `fixed`; `pin` indexes last; every button carries its **authored** index, and that
  index is what is recorded (keep `choiceOrder` and `recordAnswer`'s current signature
  `recordAnswer(q, correct, choice, ctx, conf)`; `submit(conf)` calls it with `ctx` from opts).
- `lockIn:false` (bank standalones): tap = answer, feedback at once (what the minimal card does now: verdict, `ex`,
  the picked option's `why` first, then the others, the cue after a miss, source chips, "Read: <section>").
- `lockIn:true`: tap selects (changeable), `submit()` records. With `deferFeedback:true` the card shows only
  "Recorded" and no verdict.
- `review:true`: render the answered state from history (no recording, no buttons), used by Rounds and by mock review.
- `fmt` items show the capitalized word (EXCEPT, NOT, LEAST) as it is in the stem; nothing to add.
- **Cover the options** (`STATE.ui.coverOptions`, off by default): stem and box first, options behind one "Show
  options" button. A toggle for it sits in the bank's filter row.
- **Class row** after feedback: "Class: 64% right (37 answers)" from `window.shGetClassStats`, shown only from 8
  attempts (BUILD_SPEC 6.4). Hidden when the widget isn't loaded (`file://`).
- **Report** button after feedback: `window.shOpenFlag(qid)` when it exists.
- **Recording discipline:** at most one `recordAnswer` per encounter; re-renders, Rounds and review never record.

**Cases (`25-case.js`)**

- `renderCase(el, caseId, { ctx })`: the patient box (four INBDE headings, as `pboxHTML` now) beside the items on
  desktop (box in a left column, sticky) and above them on phones (collapsible "Chart"). Items in visit order, one at
  a time, each `lockIn:true, deferFeedback:true`.
- After the last item: **Rounds**, all items with verdicts, `ex`, `why` and cues together, the box still visible.
  The section string stays `bank/cases` throughout, Rounds included (no new segment).
- A case started and left halfway resumes at the next item (keep progress in `STATE.ui`, not in a new top-level key).

**Questions mode (`40-bank.js`)**

- Sub-views `practice`, `cases`, `missed` (unchanged ids).
- Practice filters: unit, notes section (from "Practice this section", which already sets `STATE.ui.bankSec`), exam
  tag (INBDE / ADEX), New only, Hard only (class accuracy under 50% from 8 attempts). One item at a time with
  Previous / Next, as now.
- Cases: a list of case sets (patient line, number of items, done / in progress / new); tapping one opens
  `renderCase`.
- Missed: standalones whose latest try was wrong, plus case items missed (opening the case in review).
- Keep `window.SH_GOTO({qid})` working (it opens the item in Practice, or its case).
