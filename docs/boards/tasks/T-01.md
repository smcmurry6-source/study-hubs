## How to write

- **Core** (`notes.core.html`, about 2,000-3,500 words): what the exam asks, in plain words: definitions, decision
  rules, numbers to know, look-alike tables. Start with `<aside class="hy" data-unit="medcx">` holding 8-12
  high-yield lines.
- **Deep dive** (`notes.deep.html`, about 4,000-7,000 words): the mechanisms, the evidence behind each rule,
  exceptions, worked examples (for example, local anesthetic dose math from LA-1's `data`). **Same section ids in the
  same order as Core.**
- Every sentence a question could rest on ends with `<span class="ref" data-ref="FACT-ID"></span>`, and each section's
  `<footer class="sources">` lists the ids it used. Each section ends with
  `<button class="practice" data-practice="sec:<section id>">Practice this section</button>`.
- Review tables (`<table class="rt" data-rt="medcx-...">`, with `.rt-hide` on the answer columns): one for each set of
  look-alikes and one for each "numbers to know" set (for example, the blood-pressure thresholds, platelet and
  neutrophil cutoffs, emergency drug doses).
- **Fact status:** never cite an `unverified` fact. Use a `partial` fact only within what its `conditions` say. A
  `convention` fact is a teaching frame: never the reason something is right.
- **Read each fact's `conditions` before using it.** When a fact has `stem_names` (its numbers differ between
  sources), name the source in the sentence ("The ADA guide says ...", "The AAPD advises ..."). Where sources disagree,
  say so plainly and give both, as the records do.
- Your own words: no 8 or more consecutive words copied from a quote in the fact records, or from any other source.
- American English. No questions or answer keys inside the notes.

## blueprint.json

```json
{
  "unit": "medcx",
  "items_total": 60,
  "case_items": 30,
  "sections": [
    { "sec": "medcx-bleeding", "standalone": 3, "in_cases": 3, "fk": ["FK6"], "cc": ["CC8"] }
  ],
  "concepts": [
    { "concept": "dabigatran-simple-extraction", "sec": "medcx-bleeding", "refs": ["AC-2"],
      "hy": "one-line reason it is high-yield, or null", "siblings": 2, "cog": 2, "phase": "plan" }
  ],
  "cases": [
    { "id": "c-medcx-0001", "units": ["medcx"],
      "box": { "patient": "Female, 58 years old", "cc": "\"...\" (duration)", "hx": ["..."], "findings": ["..."] },
      "items": [ { "phase": "dx", "concept": "...", "refs": ["..."] } ] }
  ]
}
```

- Section quotas add up to 60 items, 30 of them in 6-8 cases of 2-6 items each. Weight the quotas toward the
  high-yield sections (BP, bleeding, endocarditis prophylaxis, diabetes, emergencies, cancer therapy).
- `fk` / `cc` codes only from the U16 row in BUILD_SPEC 3.1; `phase` from 4.4
  (`clear|dx|plan|tx|fu|prev|prof`); `cog` 1-3.
- Concepts: about 35-45; mark 8-12 of them `hy` with `siblings` 2-3 (several questions on the same concept).
- Case boxes: realistic, every fact the items will need is in the box, nothing that gives an answer away.
