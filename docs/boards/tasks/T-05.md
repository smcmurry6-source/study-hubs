## What to build

In `45-readiness-plan.js`, two layers:

**1. Pure core** (no `STATE`, `window`, `document`, `Date.now()` or `Math.random`; every input passed in):

```js
// BoardsPlan is a plain object assigned in the hub script; the test loads the same file with node:vm.
var BoardsPlan = {
  difficulty: function(stat, cog){},          // stat = [attempts, correct] or null -> {acc, b}; prior by cog (6.4)
  ability: function(events, itemsById, stats){},   // events = [{qid, correct, day, first, sibling}] in time order -> theta
  readiness: function(unit, ctx){},           // -> {likely, seen, total, band}  (6.4: bands Started/Practicing/Solid/Board-ready)
  dailyPlan: function(ctx){}                  // -> [qid]  (1.5 steps 1-4)
};
```

`ctx` carries everything: `day` ('YYYY-MM-DD'), `seed`, `items` (released, with `lec`, `cog`, `concept`, `case`),
`cases`, `history` (`STATE.answered` shape), `srs` (widget map), `stats` (`{qid:[attempts, correct]}`), `retired`,
`sureWrong` (`{qid:true}`), `budget` (`CONFIG.BUDGET`), `size`.

- **dailyPlan**: (1) budget = `size` (default 12); (2) due items by the 1.5 priority formula, ties broken by the seeded
  rng; (3) new items only while the projected due load for the next 7 days is under `governor x budget` per day, at
  most `newPerDay`; prefer a concept's first sibling before its others and spread units; (4) retirement: an item at
  the 120-day step whose last `retireStreak` answers were right is listed as newly retired (return
  `{plan:[qid], retire:[qid]}` from the core; the wrapper writes `STATE.retired`), and on the first plan of a month up
  to `retiredSamplePerMonth` retired items come back, seeded. A due item that belongs to a case is planned **alone**
  (its case box goes with it when rendered: the "follow-up visit"); never more than 3 items from one case in a day.
- **readiness**: as 6.4, with `theta_eff` decaying by days since the unit's last answer; "Adding items raises 'of N'
  without lowering 'likely'" must hold (test it).

**2. Thin hub wrappers** (use the hub's globals): `readiness(unit)` and `dailyPlan({day, size})` that build `ctx`
from `STATE`, `QUESTIONS`, `CASES`, the widget's `sh_srs_boards` map and `window.shGetClassStats` (cached; empty
stats when the widget isn't there), call `BoardsPlan`, and save `STATE.retired`. Don't wire them into Today, the drill
or the game yet (that is `int-notes-home`); just define them.

## Tests (`tools/ci/boards-plan.test.js`, plain Node with `assert`, no dependencies)

Load the file with `vm.runInNewContext` and stub the hub globals the wrappers mention (or load only the core: keep the
core above the wrappers and guard the wrappers with `typeof STATE !== 'undefined'`). Cover at least:

1. Same `ctx` gives the same plan; a different `seed` can change only tie order.
2. Plan length never exceeds `size`; no qid twice; nothing retired or unreleased in it.
3. Every due item with the top priority is in the plan when due items exceed the budget; overdue and Sure-wrong rank
   higher, as the formula says.
4. Governor: with a heavy projected load, no new items; with an empty history, exactly `min(newPerDay, size)` new.
5. Retirement after `retireStreak` right at the 120-day step; a monthly sample comes back on the 1st plan of a month.
6. Case items: at most 3 from one case a day.
7. Readiness: the four band thresholds; adding unseen items to a unit raises `total` and does not lower `likely`;
   a unit unpracticed for 120 days drifts toward the prior.
8. Fixtures `plan-*.json` (a small item set, a history and the expected plan) so later changes show up as diffs.
