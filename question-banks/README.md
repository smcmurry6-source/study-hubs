# question-banks/

Standalone question data extracted from hub pages that have been archived
off the live dashboard, kept here so a *future* hub can still pull from them
even though the original hub's own page is gone from the deployed site.

This folder is never deleted by `deploy_rollout.ps1` -- only `hubs/<name>/`
directories are removed when a hub is delisted, so anything moved here first
survives and stays reachable at a stable URL.

## gi1-question-bank.json

All 89 questions from GI Exam 1's Quiz & Review tab, extracted from its
hand-authored `.q-card` markup (that hub never had a structured `QUESTIONS`
array like the other hubs) and reshaped to match the same question format
used everywhere else in this codebase:

- `type: "mcq"` (29 questions -- 24 originally tagged Slido, 5 Vignette):
  `{id, lec, type, stem, choices, answer, ex, src}` -- same shape as any
  other hub's mcq questions. `answer` is the index into `choices`.
- `type: "recall"` (60 questions -- 45 tagged Recall, 15 tagged Vignette that
  were actually short-answer format despite the tag): `{id, lec, type, stem,
  answer, src}` -- `answer` is the full answer text (terse answer plus its
  explanation folded into one string, same as perio/hepatobiliary's own
  recall questions).

`lec` is just `"gi1"` for every entry -- the original hub never tagged
questions by lecture, only by source (`src`: `slido` / `recall` / `vignette`,
kept for provenance, not meaningful for grading).

To use this in GI Exam 2 (or anywhere else): `fetch("../../question-banks/gi1-question-bank.json").then(r => r.json())`
from a hub two folders deep (`hubs/<name>/index.html`), then treat the
result exactly like any other `QUESTIONS` array -- concat it in, filter by
`type`, feed it into a mock-exam queue builder, etc. It was NOT re-run
through the shuffle fix added for MCQ answer-position bias -- since callers
build their own queues rather than rendering these through the shared
`qCardHTML`, apply that same shuffle-on-render (or shuffle once when the
mock exam queue is built, the way hepatobiliary's `buildMockExamQueue` does
via `shuffleChoices`) rather than serving `choices` in this file's stored
order.

Regenerated by re-running `question-banks/extract_gi1.py` if `hubs/gi-exam1/`
is ever edited again before being fully deleted -- after that, this file is
the only remaining copy, so treat it as the source of truth from then on.
