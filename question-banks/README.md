# question-banks/

Standalone question data extracted from hub pages that have been archived
off the live dashboard, kept here so a *future* hub can still pull from them
even though the original hub's own page is gone from the deployed site.

This folder is never deleted by `deploy_rollout.ps1` -- only `hubs/<name>/`
directories are removed when a hub is delisted, so anything moved here first
survives and stays reachable at a stable URL.

## gi1-question-bank.json

All 89 questions from GI Exam 1's Quiz & Review tab, extracted from its
hand-authored `.q-card` markup (that hub never had a structured `QUESTIONS`
array like the other hubs) and reshaped into a single uniform MCQ format:

- Every entry is `type: "mcq"`: `{id, lec, type, stem, choices, answer, ex,
  src}` -- same shape as any other hub's mcq questions. `answer` is the
  index into `choices`.
- 29 of these were already MCQ in the original hub (24 tagged Slido, 5
  Vignette).
- The other 60 were originally free-recall/short-answer questions (45
  tagged Recall, 15 tagged Vignette but short-answer in format). Each was
  converted to MCQ by pulling the original terse answer out as the correct
  choice and writing three plausible, same-category, length-matched
  distractors around it -- the correct choice's position is spread evenly
  across the 4 (occasionally 5) options rather than clustered, so it can't
  be guessed by position alone. `src` for these is still the original tag
  (`recall`), unchanged, so provenance stays traceable even though the
  format is now MCQ. The pre-conversion recall wording (terse answer +
  explanation folded into one string) is gone from this file; if it's ever
  needed again, `hubs/gi-exam1/index.html`'s original `.q-card` markup
  still has it (kept locally, never deleted, just off the live site).

`lec` is just `"gi1"` for every entry -- the original hub never tagged
questions by lecture, only by source (`src`: `slido` / `recall` / `vignette`,
kept for provenance, not meaningful for grading).

To use this elsewhere: `fetch("../../question-banks/gi1-question-bank.json").then(r => r.json())`
from a hub two folders deep (`hubs/<name>/index.html`), then treat the
result exactly like any other `QUESTIONS` array -- concat it in, filter by
`type`, feed it into a mock-exam queue builder, etc. Choices are stored in
a fixed order (not re-shuffled on every load) -- callers should shuffle at
render/queue-build time the same way hepatobiliary's `buildMockExamQueue`
shuffles via `shuffleChoices`, rather than serving `choices` in this file's
stored order on every attempt.

**Live consumer:** GI Exam 2 (`hubs/hepatobiliary/index.html`)'s Mock Exam
mode embeds all 89 of these questions directly as `EXAM1_REVIEW_POOL`
(mapped to that file's own `{id,type,src,q,ch,a,ex}` field names) and
samples 5 at random into every generated mock exam's cumulative-review
section. That embedded copy is regenerated from this JSON, not hand-edited
-- fix a question here first, then re-run the mapping to refresh the copy
in hepatobiliary.

Regenerated by re-running `question-banks/extract_gi1.py` if
`hubs/gi-exam1/index.html` is ever edited again before being fully
deleted -- note `extract_gi1.py` only reproduces the raw extraction (29
mcq / 60 recall, matching the original hub markup); the recall-to-MCQ
distractor conversion was a one-time manual/curated pass layered on top
and is not part of what that script regenerates. After `hubs/gi-exam1/` is
ever actually deleted, this file is the only remaining copy, so treat it
as the source of truth from then on.

### 2026-09-16: `topic` field added to 6 salivary-gland questions

Hepatobiliary's Mock Exam mode needed to weight its Exam-1-cumulative draw
toward the salivary-gland lecture specifically, per the course instructor's
guidance (relayed by the student maintaining that hub) that the real Exam
2's cumulative section focuses there rather than drawing evenly across all
of Exam 1. Since `lec` is uniformly `"gi1"` for every entry above -- the
original hub never tagged questions by lecture, only by `src` -- there was
no existing field to filter on. A new optional `topic` field was added to
the 6 entries that are actually about salivary glands/saliva composition,
function, or anatomy: `gi1-q5`, `gi1-q22`, `gi1-q30`, `gi1-q56`, `gi1-q65`,
`gi1-q68`. These were identified by content match, not any upstream
tagging, so double-check by reading the `stem` if a future edit needs the
exact boundary of what counts.

This is additive only -- every other entry and every existing field is
untouched, so any consumer that doesn't already know about `topic` can
keep ignoring it safely. Hepatobiliary's embedded `EXAM1_REVIEW_POOL` copy
was updated by hand to match (its own `EXAM1_SALIVARY_IDS` constant lists
the same 6 ids) since, as noted above, that copy isn't regenerated by a
script. If another salivary-relevant question is ever added here, tag it
the same way; if a hub other than hepatobiliary ever wants its own
topic-weighted draw, `topic` is the field to extend for that.

## gi2-question-bank.json

GI Exam 2 (Hepatobiliary hub) was archived off the live site on
2026-09-23 after the exam. Its whole question bank was saved here first,
exactly as the hub had it -- no reshaping, so the field names are the
hub's own, not the GI1 file's:

- Top level: `{hub, exam, archived, lectures, questions}`.
- `lectures`: the 10 lectures, `{id, num, title, who}`.
- `questions`: all 404 entries, `{id, lec, type, src, q, ...}` where `lec`
  matches a lecture `id`. Types: `mcq` (228; `ch` choices, `a` answer
  index, `ex` explanation), `recall` (143; `ans` answer text), `sequence`
  (9; `steps` in correct order), `match` (24; `pairs`). `src` is provenance
  (`hub`, `exam2-quiz`, `exam2-pollev`, `exam2-crossword`). A few carry
  `notTested: true` (instructor said it won't be tested) or a `note`.

Load from a hub two folders deep with
`fetch("../../question-banks/gi2-question-bank.json").then(r => r.json())`.
For a cumulative mock exam, filter to `type === "mcq"` and drop
`notTested`, then shuffle choices at queue-build time. Regenerate with
`node question-banks/extract_gi2.js <hepatobiliary index.html> <out.json>`
from the hub's last live copy (git history, commit before the archive, or
the local OneDrive mirror) -- the hub folder itself is no longer on the site.
